# 설계 기록 — thinkit 플러그인

무엇을 왜 그렇게 정했는지의 기록. 원칙은 [canon.md](canon.md),
구조 근거는 [structure-patterns.md](structure-patterns.md).

## 정체성

제로베이스 레포에 기초 하네스를 한 번에 세팅하고, 이미 세팅된 레포는 같은 기준으로 감사한다.
bootstrap과 audit은 **같은 판정 기준을 시점만 다르게** 적용한다 → 기준은 `principles/rules.json` 하나에 산다.

플러그인은 하나(`thinkit`)고 레포 루트가 곧 플러그인 루트다. 스택은 플러그인이 아니라 **인자**다 —
`/harness-bootstrap rn-cli`.

## 확정된 문법 — eslint-plugin-boundaries v7.1.0

v6에서 개명·변경된 것들이라 v6 예시를 그대로 쓰면 안 된다.

| 항목 | 정본 | 비고 |
| --- | --- | --- |
| 정책 배열 키 | `policies` | v6의 `rules`에서 개명 |
| 타입 셀렉터 | `type` = 첫 타입, `types` = 전체 배열 | 둘 다 유효 |
| 템플릿 | `{{ }}` | `${ }`는 deprecated |
| 메시지 변수 | `{{policy.index}}` | v6의 `{{rule.index}}`에서 개명 |
| 내부 import | `checkInternals`, 기본 `false` | 같은 엘리먼트 안은 검사 안 함 |
| 매칭 모드 | `mode`는 deprecated | `mode:"full"`은 `partialMatch:false`로 |

근거: [migration v6→v7](https://www.jsboundaries.dev/docs/releases/migration-guides/v6-to-v7/) ·
[policies](https://www.jsboundaries.dev/docs/policies/) ·
[selectors](https://www.jsboundaries.dev/docs/selectors/) ·
[dependencies](https://www.jsboundaries.dev/docs/rules/dependencies/)

`/docs/rules/dependencies/`의 옵션 스키마 블록은 아직 `rules`로 적혀 있다 — **갱신 안 된 v6 잔재다.** 그 페이지만 보면 틀린다.

## 실측으로 확인된 것

### 리졸버는 필수이고, 없으면 조용히 실패한다

리졸버 설정이 없으면 import가 파일로 해석되지 않는다. 그러면 boundaries는 대상을 unknown으로 보고,
`checkUnknownLocals`가 기본 `false`라 **전부 건너뛴다.** config는 정상으로 보이고 위반은 0건이다.

두 겹으로 막는다. 프로필이 리졸버를 스택별로 명시하고(`resolver.devDependency`까지),
생성되는 config가 `boundaries/no-unknown-dependencies`를 켠다 — 해석 실패가 조용한 통과가 아니라
경고로 나온다.

### 대조군 없는 픽스처는 틀린 config를 통과시킨다

리졸버 없이 `checkUnknownLocals: true`만 켠 변형은 **위반 3건을 전부 잡았다.** 부정 픽스처만으로는 3/3 통과다.
실제로는 모든 import가 unknown → default deny에 걸려 **전부 차단하는 config**였다.

→ 대조군은 둘 다 필요하다. 정방향 하나로는 부족하다.

| 대조군 | 무엇을 증명하나 |
| --- | --- |
| `features/c` → `entities/x` | public API를 통한 정방향 import가 해석되고 통과한다 |
| `features/d` → `./helper` | `checkInternals`가 false로 남아 슬라이스 내부는 검사되지 않는다 |

린트되지 않은 파일은 메시지가 0건이라 대조군으로선 통과처럼 보인다. 그래서 `verify-boundaries.mjs`는
**결과에 없는 대조군을 clean이 아니라 fail로 센다.**

### RN 계열은 babel 프리셋이 없으면 죽는다

`eslint-import-resolver-babel-module`이 `babel.config.js`를 로드하므로 거기 적힌 프리셋이 설치돼 있어야 한다.
없으면 MODULE_NOT_FOUND로 **크래시한다** — 조용한 통과가 아니라서 이게 옳은 실패 모드다.
프리셋은 프레임워크(react-native / expo)가 가져오는 것이라 하네스가 버전을 고정하지 않는다.

## 승인된 설계 판정

1. **단일 플러그인.** 스택은 인자. `${CLAUDE_PLUGIN_ROOT}` 문제가 사라진다.
2. **4스택**: `rn-cli` `rn-expo` `react` `next`. 전부 FSD를 쓰므로 `modules/fsd`는 선택이 아니라 기본.
   RN 둘의 공통분모는 `rn-base`라는 abstract 프로필로 뺀다 — `extends`는 한 단계만 허용한다.
3. **repo-visible 감지**: 구조적인 것(코드펜스 트리, 경로형 줄, 확장자 나열)만 machine.
   산문은 judgement로 내린다. **스택 키워드 blacklist 금지** — 오탐이 크다.
4. **대상 레포에 SKILL.md를 심지 않는다.** audit 스킬은 플러그인에 있다.
   `.claude/harness/check.mjs`와 principle 축 규칙만 심고 package.json 스크립트로 등록한다. 어텐션 비용 0.
5. **CLAUDE.md가 얇은 건 성공이다.** 대신 완료 보고를 산출물 목록으로 만든다 —
   생성 파일, 강제되는 규칙 수, CLAUDE.md 근사 토큰, check 통과 여부.
   **빈 Gotchas가 버그가 아니라 사용법이라는 게 보고에서 드러나야 한다.**
6. **boundaries가 레이어 방향과 슬라이스 격리를 모두 소유한다.**
   `import/no-restricted-paths`는 뺀다 — 두 플러그인이 인접한 일을 하면 안 된다.
   강제 못 하는 것만 `modules/fsd/rationale.md`에 판정 기준으로 남긴다.
7. **전부 보고하고 severity로 정렬한다.** 덜 보고하지 않는다 ([P5]). `--baseline`은 v1에서 뺀다.
8. **세대 의존 항목은 calibration 축으로 분리한다.** 값이 없으면 판정하지 않고 이유와 함께 info로 드러낸다.
   심을 때는 principle 축만 심는다 — calibration 값은 세대가 바뀌는 순간 낡는다.

### 심은 check.mjs의 노후화 (판정 #4 후속)

`.claude/harness/manifest.json`에 버전과 파일별 콘텐츠 해시를 기록한다. audit은 다섯 상태로 보고한다:

- `current`
- `outdated` → 재생성 제안
- `edited-locally` → 수동 병합 안내. **절대 자동으로 덮지 않는다**
- `missing`
- `unreadable` → 매니페스트 자체가 깨졌다. 심은 것의 기록이 없으므로 아무것도 수리하지 않는다

기록되는 버전은 `rules.json`의 버전 번호가 **아니라 심는 내용 전체의 해시**다
(`{rules 버전}-{해시}`). 심는 것의 절반은 `check.mjs`이고, 그 동작은 룰셋이 소유한
번호로 서술되지 않는다. 번호에만 걸어두면 **체커를 고칠 때마다 이미 옛날 사본을 든 레포에
`current`로 나간다.** 실제로 그랬다.

`outdated`는 플러그인 사본만 내릴 수 있는 판정이다 — 심은 사본에는 비교할 정본이 없다.
심은 사본은 `current`로 보고하되 "여기서는 노후 여부를 알 수 없다"를 함께 적는다.
모르는 것을 안심시키는 쪽으로 답하지 않는다.

마지막 두 줄이 나머지의 전제다. **두 테스트가 확인하지 않은 스택의 규칙 수는 보고하지 않는다.**
샌드박스에는 eslint 툴체인, RN 프리셋(`@react-native/babel-preset`, `babel-preset-expo`),
그리고 `typescript-eslint` · `typescript` · `eslint-plugin-react-hooks`가 설치돼 있어야 한다.
셋 중 하나만 없어도 config가 로드 전에 죽어 **모든 케이스가 엉뚱한 이유로 실패한다** —
그래서 두 테스트 다 시작 전에 존재를 확인하고 이름을 찍는다.

조건부 산출물은 **양방향으로** 확인해야 한다. 답이 있을 때 생기는 것만 보면,
답이 없을 때도 생기는 회귀를 놓친다 — 그 회귀가 바로 이 플러그인이 하지 않겠다고 한 일이다.

## 린트 config를 두 파일로 쪼갠 이유 (2026-08-01)

계기는 실제로 굴러가는 RN 레포의 eslint config였다. 관심사가 다섯이었고 —
recommended 세트, TS 파서, prettier, RN 규칙, 프로젝트 규칙 — **경계 정책이 들어갈 자리가
없었다.** 우리는 그때까지 `eslint.config.mjs`라는 파일명 하나를 통째로 요구하고 있었다.

`putOwned`의 세 상태에서 이건 조용한 고장이다. 레포가 규칙 한 줄을 더하면 그 파일은
`edited-locally`가 되고, 그 뒤로 **레이어 그래프가 바뀌어도 경계 정책이 재생성되지 않는다.**
헤더 주석은 "boundaries 블록을 손대지 마라"라고 적혀 있었지만 실제로 잠기는 건 파일 전체였다.
주석이 약속한 범위와 코드가 잠그는 범위가 달랐다.

| 파일 | 소유자 | 재생성 |
| --- | --- | --- |
| `eslint.config.boundaries.mjs` | 플러그인 | 매번 |
| `eslint.config.mjs` | 레포 | 손대기 전까지만 |

실측 (react, publicApi=open으로 재부트스트랩):

```
edited-locally, left alone eslint.config.mjs        <- 레포가 추가한 줄 보존
written                    eslint.config.boundaries.mjs   <- fileInternalPath 10 -> 0
```

이게 이 분리가 사는 이유 전부다. 쪼개기 전이면 두 번째 줄이 일어나지 않는다.

## 경계 밖 규칙 네 개 (2026-08-01)

같은 config에서 가져온 것. 판정 기준은 **"안 넣으면 CLAUDE.md에 문장으로 남는가"** 하나다.

| 규칙 | 왜 |
| --- | --- |
| `react-hooks/rules-of-hooks` `exhaustive-deps` | 조건부 훅과 낡은 의존성 배열은 작동하는 코드처럼 읽힌다 |
| `no-console` | 남겨진 디버그 출력은 그걸 남긴 이유보다 오래 산다. `warn` — CLI 진입점엔 정당한 용도가 있다 |
| `@typescript-eslint/no-unused-vars` + `^_` | `^_`가 핵심이다. 예외를 말할 방법이 없는 규칙은 처음 불편할 때 통째로 꺼진다 |

**넣지 않은 것과 그 이유**가 목록만큼 중요하다. `eslint:recommended`와
`@typescript-eslint/recommended`는 뺐다 — 프리셋은 마이너 범프에서 자라고, 아무도
동의한 적 없는 규칙은 급할 때 꺼지면서 **잘 돌던 규칙까지 데려간다.** 규칙은 하나씩 이름을 적는다.
`no-explicit-any`는 레포의 답이지 기본값이 아니다. prettier 계열은 이미 `prettier.config.mjs`가
소유한다. RN 전용 규칙(`no-color-literals` 등)은 4스택 공통이 아니라 뺐다.

### TS 파서가 없었다

`typescript-eslint`는 장식이 아니라 구멍 메우기였다. 생성되는 config는 줄곧
`files: ['**/*.{ts,tsx,js,jsx}']`라고 주장하면서 **파서를 한 번도 설정하지 않았다.**
`verify-boundaries.mjs`의 픽스처가 전부 `.js`라서 16개 케이스가 전부 통과하는 동안
아무도 몰랐다. 실제 레포에서 `eslint .`는 첫 타입 주석에서 죽는다.

→ 대조군에 `.ts` 파일 하나를 넣었다. 파서가 없으면 parsing error 메시지가 뜨고,
대조군은 메시지가 하나라도 있으면 실패하므로 같은 방식으로 잡힌다.

`tseslint.configs.base`는 **배열이 아니라 config 객체 하나**다 (`recommended`는 배열).
spread하면 `TypeError: tseslint.configs.base is not iterable`로 죽는다.

### devDependencies는 이제 덮어쓰지 않는다

`scaffold.mjs`가 `...profile.devDependencies`로 병합하고 있어서, 레포가 고정해둔 버전을
우리 범위로 **덮어썼다.** 리졸버 항목만 기존 값을 보존하고 나머지는 아니었다 — 일관성도 없었다.
없는 이름만 추가하도록 고쳤다. RN이 자기 typescript를 고정하는 것처럼, 고정에는 대개 이유가 있다.

이걸 고치고 나서야 `typescript`를 devDependencies에 넣을 수 있었다. `@typescript-eslint`의
파서는 `typescript` 패키지를 런타임에 요구하므로 없으면 파서 설정이 무의미하다. 덮어쓰기가
살아 있는 동안에는 넣는 순간 RN/Expo가 고정한 버전을 우리 범위로 밀어냈을 것이다 —
babel 프리셋을 고정하지 않는 것과 같은 이유로 넣을 수 없던 항목이, 병합 규칙이 바뀌자 넣을 수 있게 됐다.

## 심는 파일의 단일 소유권

`scripts/lib/planted.mjs`가 심을 파일의 목록과 내용을 모두 가진다. `scaffold.mjs`는 부트스트랩 때

`--fix`가 고치는 것은 전부 가산적이다 — 없는 제목, 등록 안 된 스크립트, 심은 그대로인 낡은 파일.

planted 사본은 정본 내용을 갖고 있지 않으므로 스스로 갱신하지 않고 재부트스트랩을 안내한다.

## README와 CLAUDE.md의 경계

README는 **아직 clone하지 않은 사람**을 향하고, CLAUDE.md는 **레포를 이미 읽을 수 있는 모델**을
향한다. `repo-visible 정보를 생성하지 않는다`가 README에 걸리지 않는 이유가 이것이다 —
`ls` 한 번이면 아는 것과, 설치를 결정하기 전에는 알 수 없는 것은 같은 문장이라도 값이 다르다.

대신 실제 위험은 중복 소유권이다. README는 CLAUDE.md의 금지 조항을 **재진술하지 않고 링크한다.**
다만 "빈 Gotchas는 버그가 아니다"는 양쪽에 남아 있다. 한쪽은 기여자에게 내리는 명령이고
다른 쪽은 사용자에게 하는 설명이라 화행이 다르지만, **금지 #3이 바뀌면 README가 함께 낡는다.**
알고 감수한 것이다. README는 모델이 로드하는 하네스가 아니므로 "어느 지시가 이기나"는 생기지 않는다.

이 레포 자신에 `check.mjs`를 돌리면 `claude-md.gotcha-section`이 warn으로 뜬다.
CLAUDE.md에 `## Gotchas` 대신 `## 어기면 안 되는 것`이 있어서다. **영어 제목을 덧붙여 통과시키지 않는다** —
이 레포는 하네스를 심는 쪽이지 심어진 쪽이 아니고, 규칙을 만족시키려고 제목을 다는 것은
이 플러그인이 다른 레포에서 잡아내는 바로 그 종류의 장식이다.

## 브라운필드에서 처음 돌려보고 고친 것

기존 하네스가 있는 실제 레포(Next 16, bun, 자체 `eslint.config.js`·`.prettierrc`,
`CLAUDE.md`가 `@AGENTS.md` 한 줄)에 처음 설치해봤다. 그린필드 픽스처가 만들 수 없는
실패 네 개가 나왔고, 전부 **읽기와 주장** 쪽이었지 생성 쪽이 아니었다.

**tsconfig를 두 스크립트가 서로 다른 이유로 못 읽었다.** `report.mjs`의 블록 주석 정규식은
`"@app/*": ["src/app/*"]`의 `/*`에서 매칭을 시작해 paths 블록을 먹었고, `alias.mjs`는 줄 주석만
벗겨서 `/* Bundler mode */` 배너에 죽었다. 둘 다 **정상적인** tsconfig에서 실패한 것이다 —
alias glob은 예외가 아니라 표준 형태다. 문자열 상태를 추적하는 스캐너를 `lib/jsonc.mjs`에 두고
양쪽이 같은 것을 쓴다. 결과: strict 플래그 `0 → 5`, alias `1 → 5`.

`path consistency 1`은 더 나빴다. 프로필 기본 alias를 세고 있었는데, 레포의 tsconfig는
`exists, left alone`이라 그 테이블은 **어디에도 쓰이지 않았다.** 존재하지 않는 파일을 세고 있었다.

**소유권과 강제력은 다른 축이다.** `putOwned`는 정확한 경로로 소유를 정하고, 도구는 **파일명
패밀리 위의 우선순위**로 효력을 정한다. ESLint는 `eslint.config.js`를 찾으면 `.mjs`를 보지 않고,
Prettier는 `.prettierrc`를 `prettier.config.mjs`보다 앞에 둔다. 그래서 두 문장이 동시에 참이었다 —
생성된 파일은 우리 것이고, 아무것도 그것을 로드하지 않는다. `report.mjs`는 앞의 사실만 보고
`total 25`를 출력했다. 실측은 `--print-config` 기준 boundaries 규칙 **0개**.

`lib/precedence.mjs`가 각 도구의 공표된 해석 순서를 들고 있고, 가려진 줄은 `generated but
shadowed`로 표시된 뒤 합계에서 빠진다. 같은 레포에서 `25 → 10`. **"이 경로가 비어 있다"는
"이 관심사를 아무도 소유하지 않는다"가 아니다.**

**CLAUDE.md가 `@AGENTS.md` 한 줄이면 audit이 아무것도 못 봤다.** 3토큰으로 측정하고, 산문을 읽는
규칙 전부가 산문이 없는 파일 위에서 돌아 아무것도 보고하지 않았다. import를 따라가게 하니
1356토큰이 되고 `directory tree in a fenced block`이 떴다 — 이 플러그인이 잡으라고 존재하는
바로 그 위반이 그때까지 안 보이고 있었다. `--fix`는 여전히 원본에 append한다. 확장본에 붙이면
import한 파일을 importer 안으로 인라인해놓고 수리라고 부르게 된다.

**그 원본이 포인터면 제목이 규칙과 갈라졌다.** import를 따라가는 것은 판정만 고쳤고, 수리는
계속 CLAUDE.md에 썼다. 같은 형태의 레포에서 `--fix`가 남긴 것은 `@AGENTS.md` 한 줄과 그 아래
빈 `## 함정` 하나였다 — 함정을 쓰려고 여는 파일은 규칙이 사는 AGENTS.md인데, 제목은 그것을
가리키는 파일에 앉아 있다. 이제 append 대상은 **산문이 사는 raw 파일**이다. import가 여럿이거나
CLAUDE.md가 자기 산문도 지니면 어느 쪽인지 알 수 없으므로 CLAUDE.md에 남긴다. 모르면서 남의
파일을 고르지 않는다.

**프로필의 resolver 핀이 죽어 있었다.** `{...profile.devDependencies, [resolver.devDependency]: "*"}`에서
계산된 키가 뒤에 와서 `^4`를 `*`로 덮었다. 생성된 config가 아예 해석되느냐를 결정하는 그 의존성만
핀이 없었다. 순서를 뒤집었다.

테스트는 `tests/verify-brownfield.mjs`. 샌드박스가 필요 없다 — 검증 대상이 생성된 규칙이 무엇을
잡느냐가 아니라 **스크립트가 무엇을 읽고 무엇을 주장하느냐**이기 때문이다. 여기 있는 케이스는
전부 실제 레포에서 먼저 관측된 뒤에 적혔다.

**인터뷰 답이 갈 곳 없이 버려지고, 그 자리에 거짓 에러가 남았다.** CLAUDE.md가 이미 있는 레포에서
Q2의 안전 경계는 쓰일 자리가 없다 — 그 섹션이 사는 파일이 정확히 그 CLAUDE.md다. 그런데 매니페스트에는
`declared: true`가 기록됐고, 이후 모든 `harness:check`가 `"declared at setup but the section is gone"`을
`error`로 뱉었다. 사라진 게 아니라 **쓰인 적이 없다.** 영구히 실패하는 체크에 틀린 문장이 붙은 것이다.

**진짜로 사라진 경우는 `--fix`가 손대지 못했다.** 우리가 쓴 `## 안전 경계`를 레포가 지우면 규칙은
error로 잡았지만 처치가 없었다. 부재가 의견이 아니라 사실인 것 — 함정 제목이 `--fix`에 들어 있는
바로 그 조건 — 인데 같은 모양의 다른 제목만 빠져 있었다. 이제 함정과 나란히 되살린다.

내용은 채우지 않는다. 매니페스트가 아는 것은 경계가 선언됐다는 사실뿐이고, 안다 해도 도로
펼치면 소유자가 일부러 지운 경계가 되살아난다. 그건 수리가 아니라 되돌리기고, 감사가 내릴 판단이
아니다. **빈 제목과 발견을 남기면 소유자가 정한다.**

두 제목이 함께 빠져 있으면 처치가 같은 파일에 두 번 쓴다. 메모리에 든 앞선 내용에 덧붙이면 나중
것이 먼저 쓴 제목을 지우므로, append는 매번 디스크에서 다시 읽는다.

이제 `declared`는 **답이 있고 그 파일을 우리가 썼을 때만** 참이다. 로컬에서 수정된 파일은 여전히 참으로
남는다 — 우리가 쓴 섹션을 레포가 지운 경우가 이 규칙이 존재하는 이유고, 그건 계속 잡아야 한다.

가리키는 파일을 읽어서 센다. 내용이 사라진 게 아니라 옮겨간 것이고 스크립트는 그걸 안다.
랜딩이 "1.4k → 180 토큰"이라고 쓰면 스크립트가 하지 않는 판정을 웹페이지가 대신 하는 것이 된다.
주장은 **"매 요청마다 읽히는 것이 줄었다"** 하나뿐이고, 숫자가 필요하면 `report.mjs:120`의
`length / 4`를 그대로 재사용한다. 랜딩 전용 계산식을 만들면 두 곳이 다른 값을 내고 어느 쪽이
맞는지 아무도 모른다.

Before/After는 색으로 구분하지 않는다. 라벨·위치·굵기로만 구분한다 — 색맹 사용자에게 같은 정보가
가고 흑백 인쇄에서도 읽힌다. 인용 발췌는 `site/src/content/samples/` 파일 하나로 격리했고,
permalink는 **sha 고정**이다. `blob/main/`은 대상 레포가 파일을 고치는 순간 인용이 거짓이 된다.
(Before의 인용은 뒤에서 걷어낸다 — 아래 「Before를 인용에서 자작 샘플로」. 계약은 남는다.)

**검사기에 대조군을 넣었다.** `site/scripts/verify-links.mjs`는 dist를 걸어 링크·앵커·라우트·base
접두사·pagefind 질의·UI 계약·대비비를 본다. 통과만 보면 아무것도 안 하는 검사기와 구분이 안 되므로
`--self-test`가 일부러 깨뜨린 픽스처 14개에서 각각 **기대한 코드로** 죽는지 확인하고,
온전한 픽스처 하나가 exit 0으로 끝나는지도 확인한다. `verify-boundaries`가 가르친 것과 같다.

부정 케이스 중 셋은 검사기가 **조용히 아무것도 안 하는** 경로다. 값 없는 `--base`는 base를
빈 문자열로 만들어 접두사 검사 전체를 끄고 exit 0을 냈고, 값 없는 `--search`는 검색 대신
링크 검사를 돌고 초록으로 끝났다. 앵커 검사는 `name=`까지 id로 세어서 `<meta
name="description">` 때문에 실재하지 않는 `#description`을 통과시켰다. 셋 다 통과하는
검사기와 구분이 안 되던 상태고, 지금은 각각 `USAGE`·`USAGE`·`ANCHOR`로 잡힌다.

라우트 변환도 같은 종류의 구멍이 있었다. `routeForRepoFile`이 경로의 **모양**만 보고
라우트를 만들어서, `docs/principels.md` 같은 오타가 매핑된 디렉터리 안에 있다는 이유로
`/docs/principels/`가 됐다. 링크가 라우트로 바뀌었으니 플러그인은 throw하지 않았고 빌드는
초록이었다. 라우트는 이제 **실재하는 파일에서만** 나온다.

pagefind 인덱스는 gzip이고 포맷이 사설이라 파일을 파싱하지 않는다. dist를 임시 http 서버로 띄우고
`dist/pagefind/pagefind.js`를 그대로 import해서 질의한다 — 확인하려는 것이 파일의 존재가 아니라
**한국어가 실제로 쪼개져 검색되는가**이기 때문이다. `충돌` 6건, `경계` 7건.

### 커스텀 도메인으로 옮기며 (2026-08-02)

`eeennsu.github.io/thinkit`에서 `thinkit.eunsu.pro`로 옮겼다. 도메인이 루트로 서빙되므로
하위 경로가 없고, `BASE`는 빈 문자열이 된다. 옮기기 전 배포는 자산을 `/thinkit/_astro/…`로
가리키고 있었는데 루트 도메인에서 그 경로는 전부 404다. **HTML은 200이고 CSS만 빠진다** —
페이지는 뜨고 배포는 초록이고, 사이트만 못생겨진다. 무너지는 실패보다 이쪽이 오래 간다.

**접두사 검사를 CI 스텝에서 뺐다.** `--base /thinkit`을 별도 스텝으로 두면 배포 경로가 바뀔 때
그 스텝을 고치거나 지워야 하고, 잊힌 검사는 없는 검사다. 이제 기본 실행이 `astro.config`의
`BASE`를 읽어 스스로 켜고 끈다. 끈 실행은 껐다는 사실을 출력한다 — 조용히 빠지면 통과가
"접두사도 봤다"로 읽힌다. `--base`는 그 판정을 덮어쓰는 자리로 남고, 대조군이 쓴다.

그래서 대조군 픽스처는 `astro.config`가 아니라 **자기 접두사**로 세운다. 설정을 따라가게 두면
루트로 내려간 순간 접두사 대조군이 아무것도 안 깨고 조용히 통과하고, 접두사 검사가 아직
살아 있는지 아무도 모르게 된다. 온전한 쪽(`base-ok`)을 먼저 두는 이유는 다른 대조군과 같다.

**CNAME은 아티팩트 안에 있어야 한다.** Actions로 배포하면 `site/dist`가 통째로 사이트가 되고,
커스텀 도메인은 그 안의 `CNAME` 파일로 선언된다. 없으면 배포가 도메인 설정을 풀 수 있다 —
그때 증상은 또 404다. `site/public/CNAME`에 두어 빌드마다 dist로 복사되게 했다.
HTTPS 인증서는 레포 설정 쪽이라 여기서 강제할 수 없다. 발급 전에는 `*.github.io` 인증서가
나가고 브라우저가 이름 불일치로 막는다.

### Before를 인용에서 자작 샘플로 (2026-08-02)

Before는 처음에 실재하는 공개 레포의 root AGENTS.md 발췌였다
(`anomalyco/opencode`, `blob/f44423609b03a47baf8a771c821a1de17046309f/AGENTS.md`).
증거로는 가장 강한 형태지만, 비교에서 **동시에 세 변수가 달라졌다** — 레포도 다르고, 언어도
다르고(영문 대 한국어), 장르도 달랐다. 오른쪽이 짧은 이유가 배치 때문인지 그냥 다른 파일이라
그런지 읽는 사람이 분리할 수 없다.

그래서 왼쪽을 **오른쪽과 같은 가상 레포(Storefront)를 예전 방식으로 적은 한국어 샘플**로
갈았다. 이제 달라지는 변수는 배치 하나다. 규칙 줄은 지어내지 않고 공개 레포에서 흔한 줄만
골랐고, 우리가 쓴 예시라는 사실은 블록 아래에 적는다 — 안 적으면 실재 레포의 주장으로 읽힌다.
원래 인용은 여기 남는다. 사이트 본문에서만 빠진 것이지 없던 일이 아니다.

**검사 계약은 지우지 않고 조건부로 바꿨다.** `verify-links --ui`는 Before 블록에 sha 고정
permalink와 인용 시점을 **필수**로 요구하고 있었다(U4·U5). 인용이 사라지면 이 검사는 영구
실패한다. 지우는 것이 쉬운 답이지만, 그러면 다음에 인용을 다시 넣는 사람을 아무도 막지 않는다.
인용은 **없어진 것이지 틀려도 되는 것이 아니다.** 이제 규칙은 "Before에 `github.com/…/blob/`
링크가 있으면 sha 고정이어야 하고 인용 시점이 있어야 한다"이다.

조건부 검사는 조용히 아무것도 안 하기 쉬운 모양이라 대조군을 둘 더했다. `no-citation-ok`는
인용 없는 Before가 통과하는지 보고(조건부가 "항상 실패"가 아님), `branch-permalink`와
`no-cited-at`는 인용이 있는 픽스처에서 계속 죽는다(조건부가 "항상 통과"가 아님). 픽스처는
프로덕션 페이지와 무관하게 매번 인용 블록을 세우므로, 사이트에 인용이 없어도 검사는 실행된다.

자리표시자 검사는 **별도 코드로 분리했다**(`UI_PENDING`). 예전에는 `before.md`가 비어 있으면
permalink 검사가 곁다리로 그걸 잡았는데, 인용이 선택이 된 지금은 그 곁다리가 사라진다.
자리표시자인 채로 배포되는 것은 여전히 버그이므로 직접 본다. 부정 케이스도 같이 뒀다.

Node는 22 계열에서 실측했다 (로컬 22.12.0, CI `setup-node@v4` `22`).

버려졌다는 사실 자체도 출력한다. `written` 목록의 `CLAUDE.md: exists, left alone`은 대개 무해한
결과라서, 답 하나가 증발했다는 신호로는 읽히지 않는다. 이 실행에서 레포 주인이 손대야 하는 유일한
항목이므로 요약에 `note`로 올린다.

**FSD 레이어가 아닌 디렉터리를 둘 곳이 없었다.** `boundaries/elements`는 `layers.json`과
`routingRoot`로만 만들어져서, 그 밖의 디렉터리로 가는 import는 전부 `no-unknown-dependencies`가 된다.
하네스보다 먼저 있던 레포에는 그런 게 항상 있다 — `src/db`, `src/data`, `src/subjects`. 린트가
`--max-warnings 0`으로 도는 레포에서 이건 finding이 아니라 **켤 수 없는 config**다.

어떤 디렉터리가 있는지는 repo-visible이므로 `routingRoot`와 같은 대접을 한다 — 묻지 않고 읽는다.
그것들이 무엇을 뜻하는지는 repo-visible이 아니므로, **가장 적게 틀릴 수 있는 자리**에 둔다: 그래프
맨 아래. 무엇이든 그것을 import할 수 있고, 그것은 맨 아래 레이어와 서로만 import한다. `shared`가
이미 갖고 있는 위치이고, 레이어 그래프가 주지 않은 권한을 하나도 추가하지 않는 유일한 자리다.

더 준다면 레이어 밖으로 코드를 옮겨 레이어 그래프를 빠져나가는 길이 열린다. `extraRoots` 답으로
덮을 수 있고, `[]`는 "그냥 unknown으로 보고해라"는 유효한 답이다. 배치는 요약에 출력한다 —
읽어서 정한 값이 조용히 정책이 되면 안 된다.

실측: 이 레포의 위반이 24건에서 2건으로 떨어졌다. 사라진 것 중 4건이 `@db` 오탐이었고,
나머지는 `publicApi=open` 답이 처리했다. 남은 2건은 둘 다 진짜다.

**`warn`이 `error`와 같아지는 레포가 있다.** Q4의 기본값이 기존 코드에서 `warn`인 이유는
`error`가 첫 실행을 뒤덮고 그러면 규칙이 꺼지기 때문이다. 그 근거는 **경고가 견딜 만하다**는 것을
전제한다. 린트 스크립트가 `--max-warnings 0`으로 돌면 경고 하나가 명령을 실패시키므로 두 답이
같은 답이 되고, 그 린트를 빌드가 부르면 같은 빌드가 된다.

읽을 수 있는 사실이므로 읽어서 말해준다. 기본값을 바꾸지는 않는다 — `severity=off`가 그 레포의
올바른 답일 수 있지만 그건 레포 주인이 정할 것이고, 여기서 할 일은 그 선택이 존재한다는 걸
보이지 않게 두지 않는 것이다.

**우선순위에서 진 것과 안 쓰이는 것은 다르다.** 보고서가 레포에게 "당신 entry config에 우리 걸
spread하라"고 시켜놓고, 정확히 그렇게 한 레포를 `shadowed`로 보고했다. `eslint.config.js`는 여전히
lookup을 이기지만, 이제 그 안에서 생성된 정책을 import한다. 제대로 연결된 하네스를 죽었다고 말하는
것은 이 파일이 막으려던 숫자와 방향만 반대인 같은 종류의 거짓이다.

판정은 승자 파일 안에 우리 파일 이름이 있는지로 한다. 텍스트 매칭이라 런타임에 조립한 경로는 놓치는데,
그 경우 `shadowed` 쪽으로 틀린다 — 안전한 방향이다. 그리고 "연결됨"은 줄마다 달지 않고 블록 아래
한 줄로 말한다. 그건 실행 전체에 대한 사실이 하나 있는 것이지 네 줄이 각각 달라지는 게 아니고,
줄 옆자리는 `answered: publicApi=open` 같은 변형 설명이 써야 한다.

**레이어 디렉터리는 빈 레포에만 만든다.** 빈 레포에서는 그게 요점이다 — 아무것도 넣을 데가 없는
레이어 그래프는 문서다. 이미 코드가 있는 레포에서는 정반대다. 그 레포에 한 번도 없었던 레이어의
`src/entities/.gitkeep`은 아무도 요청하지 않은 디렉터리이고, 아무도 원하지 않은 diff이며,
**정책은 디렉터리가 없어도 그대로 생성된다.** 매칭될 파일이 없을 뿐이고 그건 어느 쪽이든 같다.

판정은 읽어서 한다: `fsdRoot` 아래에 우리가 심은 `.gitkeep` 말고 뭔가 있으면 코드가 있는 것이다.
그 예외가 필요한 이유는 빈 상태에서 bootstrap한 레포를 다시 돌릴 때다 — 우리 출력을 레포의 입력으로
읽으면 두 번째 실행이 첫 번째와 다른 답을 낸다.

없는 레이어는 만들지 않는 대신 **이름을 불러준다.** 그리고 report는 그래프가 가진 수가 아니라
디스크에 있는 수를 센다. `6 layer directories under src/`는 만든 적 없는 디렉터리를 세고 있었다.

**산문은 AGENTS.md에 살고 CLAUDE.md는 그것을 가리킨다.** 하네스를 읽는 도구가 Claude Code 하나가
아니다. 같은 규칙을 파일 둘에 두 벌 두면 그 둘은 반드시 갈라지고, 갈라진 뒤에는 어느 쪽이 맞는지
아무도 모른다. 포인터는 갈라질 자리를 없앤다 — `CLAUDE.md`는 `@AGENTS.md` 한 줄이고 규칙도 함정도
안전 경계도 AGENTS.md에만 있다.

읽는 쪽은 이미 준비돼 있었다. `check.mjs`가 `@`를 펼쳐서 감사하고 `proseFile()`이 포인터가 아니라
산문이 사는 파일을 고르므로, 토큰 측정도 `--fix`의 제목 복구도 옮긴 뒤에 달라지는 것이 없다.
`report.mjs`만 포인터를 3토큰으로 재고 있었다 — 재지 않은 것을 잰 것처럼 보이는 값이라 함께 고쳤다.

**쓰는 조건이 셋인 이유.** CLAUDE.md이 없거나, 우리가 쓴 것이거나, 이미 `@AGENTS.md` 한 줄일 때만
쓴다. 자기 산문을 CLAUDE.md에 가진 레포 옆에 AGENTS.md를 새로 만들면 규칙이 두 곳에 살고 어느
쪽도 다른 쪽을 가리키지 않는데, 그게 이 배치가 막으려던 상태 자체다. 다른 곳을 가리키는
포인터(`@docs/rules.md`)도 남의 산문이고 같은 대접을 받는다 — 덮어쓰면 그 레포의 하네스가 우리
것을 가리키게 되고 원본은 아무도 읽지 않는다.

AGENTS.md만 있고 CLAUDE.md이 없는 레포는 반대다. 산문은 그쪽 것이므로 두고 없는 포인터만 만든다.
하네스를 옮기는 것이 아니라 닿게 하는 것이다.

### 화면을 실제로 띄워 고친 것 (2026-08-03)

브라우저로 렌더해서 잡은 것들이다. 빌드도 링크 검사도 대비 검사도 전부 초록인 상태에서 나왔다 —
초록이 "봤다"는 뜻이 아니라는 것이 이 목록의 요점이다.

**한국어는 브라우저 기본값으로 두면 어절 한가운데에서 끊긴다.** `word-break: normal`은 한글을
음절 단위로 끊을 수 있는 것으로 보고 "계속 얇게 유지시 / 켜주는"을 만든다. 영어에 없는 문제라
테마가 손대지 않는다. `keep-all`로 막고, 끊을 자리가 없는 긴 토큰용으로 `overflow-wrap`을 함께 건다.

표에서 이게 한 번 깨졌다. 칸 폭이 내용에 끌려다니는데 어절이 통짜가 되면 최소 폭이 어절 길이만큼
올라가고, 자리가 모자란 칸부터 다시 쪼갠다. 칸 안에서만 쪼개기를 허용하는 것은 keep-all을 표에서만
되돌리는 것이다. **쪼개는 대신 표가 자기 안에서 가로로 스크롤한다.** `display: block`이 표의 접근성
역할을 지운다는 통설이 있어 Chrome·Firefox·WebKit 세 엔진에서 aria 트리를 떠 봤다 —
`table / rowgroup / row / columnheader`가 그대로다.

**넘쳤다는 것은 CSS가 알 수 없다.** 그래서 재서 클래스를 단다. 안 넘치는 것까지 표시가 붙으면
그 표시는 아무것도 뜻하지 않게 된다. 표시 자체는 두 번 틀렸다. 검정 반투명 그림자는 어두운 테마에서
어두운 배경 위의 어두운 그림자라 보이지 않았고, 스크롤바에 맡기는 것은 겹침 스크롤바를 쓰는
환경에서 자리도 안 차지하고 만지기 전에는 보이지도 않았다. 지금은 `currentColor`에서 뽑는다 —
본문 색은 정의상 그 블록 배경과 대비되므로 테마를 나눠 적을 필요가 없다.

**"보인다"를 눈이 아니라 픽셀로 쟀다.** 같은 띠에서 표시를 껐다 켜서 평균 밝기 차를 본다. 띠끼리
비교하면 안 된다 — 띠의 평균은 거기 들어간 글자 양에 먼저 좌우된다. 이 방법으로 덮개가 표시 폭을
다 못 덮어 끝까지 밀어도 잔상이 남는 것을 잡았다. 끝까지 밀었는데도 "더 있다"고 말하는 표시는
거짓말이다.

**줄바꿈 검출기도 대조군이 필요했다.** 처음에는 공백으로 토큰을 잘라서 `Auto-memory`,
`(2026-08-01)`, `팀·제품`까지 결함으로 셌다. 그건 어느 언어에서나 정상 줄바꿈이고 막으면 좁은
화면에서 그 토큰이 칸을 넘긴다. 경계 양쪽이 모두 한글일 때만 세도록 좁힌 뒤 `word-break: normal`을
주입해 285건이 나오는 것을 확인했다. 0을 내는 검사기와 아무것도 안 하는 검사기는 대조군 없이는
같아 보인다.

**계획서의 판정 하나가 틀렸다.** "Before/After 두 칼럼 높이가 크게 다르다"고 적었는데 실측은
1475 대 1459였다. 그리드 stretch로 박스는 이미 맞고, 눈에 띈 것은 After 내용이 일찍 끝나서 생긴
박스 안 여백이었다. 고칠 것이 없었다.

### 스크린샷으로만 알던 것을 검사기로 옮겼다 (2026-08-03)

위에서 고친 것 중 넷은 dist만 보면 판정된다. 사람이 화면을 봐야 아는 것이 아니었고, 그래서
`verify-links.mjs`에 있다 — 레포 규칙이 "도구로 강제 가능한 건 문서에서 뺀다"이고, 이것들은 한 번
고친 뒤 조용히 되돌아오는 종류다.

| 검사 | 무엇을 막나 |
| --- | --- |
| `META_TITLE` | 문서 제목이 사이트 이름과 같아 `thinkit \| thinkit`이 되는 것 |
| `META_LANG` | 한국어 전용 사이트에 우리 문서 제목만 영어로 남는 것 |
| `META_SELF_URL` | 본문이 자기 사이트를 절대 URL로 가리키는 것 |
| `META_OG` · `META_ROBOTS` | 공유 카드가 빈 채로 나가는 것 |

`META_TITLE`은 사이트 이름을 검사기에 적지 않는다. `|`로 나눈 조각 중 같은 것이 두 번이면 무엇이든
중복이다. `META_LANG`은 예외 셋을 명시한다 — 아카이브(제목이 원저자의 것), 랜딩(h1이 워드마크),
404(숫자). 예외를 안 적으면 이 검사는 옳은 것을 잡느라 꺼지게 된다. 그래서 아카이브의 영어 제목이
통과하는지를 보는 대조군이 부정 케이스 옆에 같이 있다.

`META_OG`는 태그가 있는지만 보지 않고 **가리키는 파일이 dist에 실재하는지까지 본다.** 있다고만
보면 파일 이름을 바꾼 날 죽은 이미지를 초록으로 배포한다.

**OG 이미지는 커밋하지 않는다.** `scripts/og-image.mjs`가 `custom.css`의 색을 읽어 빌드 전에
만든다. 커밋하면 강조색을 바꿨을 때 PNG만 옛 색으로 남고, 그 사실은 공유해 보기 전에는 모른다.
색 읽는 규약은 `scripts/theme-colors.mjs` 한 곳에 있고 대비 검사와 OG 생성이 둘 다 거기서 읽는다.
값 자체는 여전히 `custom.css`에만 산다.
